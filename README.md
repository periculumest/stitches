# Stitch Helper

A private cross-stitch workspace with Google sign-in, PostgreSQL persistence, multi-device progress, blended floss, and portable user backups. Built with ASP.NET Core 8, React/TypeScript, and Canvas.

## Set up development

Requires .NET 8 SDK/runtime, Node.js 22, PostgreSQL 17 (Docker Compose is provided), and a Google OAuth web client for interactive sign-in.

```powershell
docker compose up -d postgres
# Configure Authentication:Google:ClientId and ClientSecret through .NET user secrets.
.\Start.ps1 -Migrate
```

Open **http://127.0.0.1:5057**. Register `http://127.0.0.1:5057/signin-google` on the development OAuth client. See the [preproduction setup guide](<docs/phase 2/PREPROD-READINESS.md>) for the exact Google setup and hosted deployment steps.

Later launches can use `./Start.ps1 -SkipBuild`. Migrations are explicit; use `-Migrate` after schema changes. PostgreSQL defaults to port 5433 with the development-only credentials in `server/appsettings.Development.json`. Override the connection through `ConnectionStrings__StitchHelper` or user secrets. Private development objects default to `.data/private`, outside the web root.

For separate frontend development:

```powershell
$env:ASPNETCORE_ENVIRONMENT='Development'
dotnet run --project server
# In another terminal:
npm --prefix web run dev
```

Open `http://127.0.0.1:5173` and register that origin's `/signin-google` callback. Vite proxies `/api`, `/auth`, and `/signin-google` to the API.

There is no guest login or SQLite fallback. Old local SQLite data is not migrated; existing local files have not been deleted.

## Use the workspace

1. Sign in with Google, then try the garden sampler or import a PDF.
2. Review the extracted chart, original PDF, warnings, symbols, thread components, and page placement before confirming an import.
3. Select definitions in the key, filter/isolate matching stitches, pan/zoom, or enter **Focus pattern**.
4. Paint complete/incomplete, set a working area, or apply completion to matching stitches. Progress has undo/redo and visible save/retry status.
5. Open another browser with the same account. Saved progress refreshes on focus and every 30 seconds while the project is active. Stale aggregate edits report a conflict.
6. Edit a definition to add blend components with optional strand counts. The **Threads** panel shows required physical floss and reversible substitutions for individual components.
7. Record bobbin counts and locations in **Thread collection**.
8. Use **Backups & Export** to download current data or the latest retained daily/weekly archive. Automatic backups require the operator's scheduled jobs.

Project deletion is permanent. Deleting the last project using a pattern also removes its source PDF, and any project deletion invalidates existing retained backups. Account deletion is available under **Account & data**. See [retention and deletion](docs/DATA-RETENTION.md) for cleanup retries, archive expiry, deployment steps, and the infrastructure policies still needed for the full privacy policy. The public explanation is `/data-retention`.

The 489-color DMC catalog in `data/thread-catalog/rgb-dmc.json` is shared reference data, refreshed by the migration/release command. It includes DMC 1–35 from the supplied `MissingColors.xlsx`, using the workbook's names and swatch RGB values. Numeric codes ignore leading zeros, so patterns using `05` resolve to DMC `5`. Users' inventory is private. Screen colors may differ from physical floss.

## Import support

The importer supports simple vector-grid/text-key PDFs and the numbered symbol-font chart-table format described in the [PDF assessment](docs/PDF-IMPORT-ASSESSMENT.md). The supplied sample produces a verified 200 × 300 chart with 60,000 stitches and 78 colors. Every import opens for review.

Explicit `310 + 321` blend notation and specified component strand counts are supported. Ambiguous legends, scans, unsupported encodings/layouts, and specialty stitches still need review or a different source format. Broad commercial-publisher compatibility is not claimed.

Imports default to a 45 MB maximum; `Import__MaxMegabytes` can lower it for hosted ingress. The UI shows the configured limit. Sources remain private and are retained even when extraction fails.

## Validate

```powershell
# PostgreSQL must allow creation of isolated test databases.
.\Test.ps1
# Dependencies already installed:
.\Test.ps1 -SkipInstall
# Alternate test PostgreSQL:
.\Test.ps1 -PostgresConnection 'Host=localhost;Port=5433;Database=postgres;Username=stitch;Password=local-development-only'
```

The script runs backend security/concurrency/import/backup tests, Chrome browser workflows, daily/weekly job commands, and restart checks. Test-only cookies are generated by a separate executable excluded from deployment. Artifacts and browser test databases are retained for inspection.

For backend tests only, set `STITCH_TEST_POSTGRES` and run `dotnet test tests/StitchHelper.Tests.csproj`. Without that setting, PostgreSQL integration tests explicitly skip; this is **not** a release validation run. CI supplies PostgreSQL and includes the container build.

## Deploy

The [preproduction readiness guide](<docs/phase 2/PREPROD-READINESS.md>) covers hosting, domain selection, Google OAuth, database/buckets, service accounts, secrets, certificate setup, migration jobs, scheduled backups, and release rehearsal.

```text
docker build --build-arg APP_VERSION=0.2.0 -t stitch-helper:0.2.0 .
```

The image serves React and the API on one origin. Production requires external PostgreSQL, private Google Cloud Storage, Google OAuth credentials, an HTTPS public origin, and a supplied Data Protection certificate. Use the same image with `--migrate`, `--backup daily`, or `--backup weekly` for release/scheduled jobs. Health endpoints are `/health/live` and `/health/ready`.

Live Google login, cloud storage, and complete container replacement must be rehearsed in your environment before release. Public-commercial-launch work remains in the phase 2 backlog.
