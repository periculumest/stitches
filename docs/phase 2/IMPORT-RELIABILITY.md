# Import reliability: findings and proposed next steps

Date: 2026-09-07. This document records recommendations after the two supplied production-style PDF samples. The improvements below are proposed, not implemented by this review.

Follow-up: the [visual page builder](PAGE-BUILDER.md) now implements draft page arrangement, join checks, and atomic correction saves from item 3 below. Source overlap preservation supports reversible placement. Other recommendations remain proposed unless documented separately.

## What the samples taught us

- Support format families, rather than filenames. The existing chart-table and Cross Stitch Professional adapters recognize document features; other exports with the same structure may work, but two fixtures do not establish broad compatibility.
- Read layout geometrically. PDF text order and spacing do not reliably reproduce the visible legend. Column boundaries keep numeric-looking symbols separate from DMC codes, including multi-column keys. PdfPig explicitly cautions against relying on `page.Text` for reading order: [PdfPig documentation](https://github.com/UglyToad/PdfPig).
- Preserve symbol identity and shape. A printable character alone is insufficient; our adapters combine font identity and character value and retain outlines. A shared font frame preserves relative symbol sizes. Future fixtures must challenge subset-font name collisions and different glyphs with identical decoded text; stripping a subset prefix is not a universal identity guarantee.
- Locate cells independently of glyph bearings. Iron Man required vector grid geometry because symbol baseline offsets varied. The earlier adapter uses a symbol lattice. A shared engine should support both methods, cross-check them where possible, and distinguish blank fabric from missing extraction.
- Page order is insufficient evidence of placement. Printed coordinates, zero/one-based numbering, repeated overlap strips, and declared dimensions matter. Matching overlaps may be deduplicated; conflicting overlaps require correction.
- Validation evidence varies by document. The first sample provides thread usage totals; Iron Man does not. Both can be checked for dimensions, placements, symbol mappings, and overlaps. A rectangular footprint alone cannot prove every stitch was extracted.

## Preprocessing and sanitization

Retain the uploaded original unchanged and normalize extracted data into an internal page model: coordinates, rotation/crop transforms, text positions, font/glyph references, paths, and candidate chart/key regions. Preserve source coordinates so review can point back to the original. Normalize legend text separately from chart symbols; do not replace symbol characters as ordinary text cleanup.

Do not routinely print to PDF, flatten, rasterize, remove fonts, or force OCR. Such transformations can remove the vector/text evidence these adapters use. For example, OCRmyPDF documents that forced OCR rasterizes printable text and vector content: [OCRmyPDF advanced features](https://ocrmypdf.readthedocs.io/en/stable/advanced.html).

Consider structural repair only as a bounded retry when opening/parsing fails, using a derived copy with recorded tool/version and repair warnings. Run all chart validation again. qpdf can recover some damaged structures, but its structural check does not establish semantic correctness: [qpdf design notes](https://qpdf.readthedocs.io/en/stable/design.html), [qpdf check documentation](https://qpdf.readthedocs.io/en/12.0/cli.html#option-check). Repair cannot supply a missing legend or infer the intended page arrangement. No repair dependency is selected yet.

Security validation is a separate concern from chart accuracy. Existing upload-size, signature, and page-count checks are useful; parsing still runs synchronously inside the web process without a parser cancellation budget. Add bounded concurrent imports and a worker process with enforceable time/memory limits. A request timeout alone cannot stop an uncooperative parser. Do not interpret a structurally valid PDF as safe or correctly extracted.

## Recommended implementation order

1. **Consistent checks and useful diagnostics.** Extract common geometry, glyph, placement, and validation helpers. Classify outcomes as verified checks passed, needs correction, unsupported features, or unreadable input. Record adapter/version, failed stage, page references, evidence and missing checks. Keep review required even when automated checks pass. Replace generic multi-page stacking with an explicit placement task; do not present a guess as verified extraction. Identify unaccounted pages/marks and unsupported specialty stitches, with unresolved extraction gaps preventing confirmation.
2. **A broader regression collection.** Add permitted samples from different exporters and variations within each family: sparse charts, blank margins, rotated pages, reordered tiles, multiple keys, overlaps, blends, fractional stitches/backstitch, image-only charts, damaged files, and ambiguous fonts. Maintain independently checked dimensions, selected cell mappings, counts when available, and visual comparisons. Each resolved report should contribute a fixture when sharing rights permit. Track manual corrections and confirmed incorrect imports as well as parser failures.
3. **Guided repair within review.** Let users identify chart/key pages, select a chart rectangle, calibrate the grid, correct page placement, and map unresolved symbols using source snippets. Show source and extracted cells together. Re-run checks after corrections. Existing page-offset and key editing provide a starting point; grid calibration and aligned source review still need implementation.
4. **Recoverable import jobs and private support reports.** Move parsing into bounded jobs with progress, cancellation, retry, and persisted diagnostics. Keep report metadata minimal and provide explicit user-controlled sharing of source PDFs; uploading a private pattern is not permission to share it with support. Allow a new importer version to create a comparison draft from the retained original. Preserve existing projects and progress; transfer completion only after stitch correspondence is validated and the user accepts the result.
5. **Separate image-based recognition.** Add scanned/outlined-chart support after the vector pipeline is dependable. Detect the grid and match cell shapes against the document's own legend; use OCR primarily for thread codes and labels. Keep ambiguous cells unresolved and require review. Evaluate any recognition model on held-out samples before broadening support claims.

The first delivery should combine common validation, structured diagnostics, and broader fixtures, alongside enforceable parsing limits before public rollout. These improve existing imports and make future adapters cheaper to diagnose. Automatic repair and image recognition should follow evidence from actual failures.
